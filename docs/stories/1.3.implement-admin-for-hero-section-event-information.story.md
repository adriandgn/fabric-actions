# Story 1.3: Implement Admin for Hero Section Event Information

## Status
Ready for Review

## Story
**As a** content administrator,
**I want to** update the event information displayed in the Hero section,
**so that** I can easily manage details like last exhibition, next exhibition, date, and address.

## Acceptance Criteria
1.  Admin page `/admin/exhibition-info` exists and is accessible to authenticated users.
2.  The page displays a single form to edit the "Exhibition Info" (last exhibition, next exhibition, next exhibition date, next exhibition address).
3.  Changes saved in the admin form are reflected on the public-facing Hero section.

## Tasks / Subtasks
- [x] **Task 1: Create Supabase Table and RLS Policy**
    - [x] Create `exhibition_info` table in Supabase (single row table).
    - [x] Implement Row Level Security (RLS) policy for `exhibition_info` table to allow authenticated admin users read/update access.
    - [x] Create Supabase migration file for the new table.
- [x] **Task 2: Develop Admin Page (`ExhibitionInfoPage.tsx`)**
    - [x] Create `src/pages/admin/ExhibitionInfoPage.tsx`.
    - [x] Implement data fetching for exhibition info using `react-query` and `supabase-js`.
    - [x] Display a single form to edit the exhibition info.
    - [x] Integrate with `App.tsx` routing for `/admin/exhibition-info`.
- [x] **Task 3: Modify Public-Facing Component (`Hero.tsx`)**
    - [x] Modify `src/components/Hero.tsx` to fetch data from Supabase instead of using hardcoded data.
    - [x] Ensure the public Hero section displays the dynamically fetched data correctly.
    - [x] Verify visual consistency and and performance after data integration.
- [x] **Task 4: Write Unit and Integration Tests**
    - [x] Write unit tests for `ExhibitionInfoPage.tsx`.
    - [x] Write integration tests to verify data flow between frontend and Supabase for update operations.
