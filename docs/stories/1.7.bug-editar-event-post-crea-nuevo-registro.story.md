Title: Bug: Al editar Event Post se crea nuevo registro en lugar de actualizar
Status: Ready for Review
Story: |
  Como administrador,
  quiero que al editar un Event Post existente y presionar "Save Event Post",
  los cambios se guarden en el registro original,
  para evitar la duplicación de Event Posts y mantener la integridad de los datos.
Acceptance Criteria:
  - Al editar un Event Post existente en `/admin/event-posts` y presionar el botón "Save Event Post", el registro original debe ser actualizado con los nuevos datos.
  - No se debe crear un nuevo registro de Event Post en la base de datos al intentar editar uno existente.
  - La lista de Event Posts en `/admin/event-posts` debe reflejar la actualización del registro existente, sin mostrar duplicados.
Dev Notes:
  Contexto del Proyecto: Aplicación de una sola página (SPA) construida con React (v18) y TypeScript. Utiliza `react-hook-form` para formularios y Supabase para la base de datos.
  Componentes Relevantes:
    - `src/pages/admin/EventPostsPage.tsx`: Maneja la lógica de abrir el formulario de edición y pasar el `eventPost` actual.
    - `src/pages/admin/EventPostForm.tsx`: Contiene el formulario de edición/creación y la lógica de `upsert` con Supabase.
  Problema Identificado: Al editar un `Event Post`, la operación `upsert` en `EventPostForm.tsx` está creando un nuevo registro en lugar de actualizar el existente. Esto sugiere que el `id` del `Event Post` que se está editando no se está pasando correctamente a la función `upsert` de Supabase, o que Supabase no lo está reconociendo para la actualización.
  Hipótesis de Causa Raíz:
    - El `id` del `eventPost` no se está incluyendo en el objeto `data` que se pasa a `supabase.from('event_posts').upsert(data)`.
    - El `id` se está pasando, pero hay un problema con el tipo de dato o el formato que impide que Supabase lo reconozca como una clave existente para la actualización.
  Referencia: La documentación de Supabase `upsert` indica que si se proporciona una clave primaria existente, el registro se actualizará; de lo contrario, se insertará uno nuevo.
Tasks / Subtasks:

  - [x] Asegurar que el `id` del `Event Post` que se está editando se incluya correctamente en el objeto `data` que se pasa a `supabase.from('event_posts').upsert(data)`.
  - [x] Verificar que el `id` se esté pasando con el tipo de dato y formato correctos para que Supabase lo reconozca como una clave existente para la actualización.
  - [x] Probar la funcionalidad de edición y guardar para confirmar que el registro existente se actualiza y no se crea uno nuevo.
  - [x] Realizar pruebas de regresión para la creación de nuevos Event Posts para asegurar que esa funcionalidad no se vea afectada.
