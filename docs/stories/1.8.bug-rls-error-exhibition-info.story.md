Title: Bug: Error de RLS al actualizar Exhibition Info en Admin
Status: Draft
Story: |
  Como administrador,
  quiero poder guardar las modificaciones del formulario de "Exhibition Info" en `/admin/exhibition-info` sin errores de seguridad,
  para asegurar que la información de la exposición se actualice correctamente en la base de datos.
Acceptance Criteria:
  - Al intentar guardar las modificaciones en el formulario de "Exhibition Info" en `/admin/exhibition-info`, no debe aparecer el error "Error: Failed to update exhibition info: new row violates row-level security policy for table "exhibition_info"".
  - Los cambios realizados en el formulario deben guardarse exitosamente en la base de datos.
  - La información actualizada debe reflejarse correctamente al recargar la página o al volver a acceder a la sección "Exhibition Info".
Dev Notes:
  Contexto del Proyecto: Aplicación de una sola página (SPA) construida con React (v18) y TypeScript. Utiliza Supabase como backend, incluyendo sus políticas de Row-Level Security (RLS).
  Componentes Relevantes:
    - `src/pages/admin/ExhibitionInfoPage.tsx`: Maneja la lógica de la página de administración de información de la exposición.
    - `src/pages/admin/ExhibitionInfoForm.tsx`: Contiene el formulario para editar la información de la exposición y la lógica de guardado.
  Problema Identificado: Al intentar actualizar la tabla `exhibition_info` desde el panel de administración, Supabase deniega la operación debido a una violación de la política de seguridad a nivel de fila (RLS). El mensaje de error específico es: "new row violates row-level security policy for table "exhibition_info"".
  Hipótesis de Causa Raíz: La política de RLS definida para la tabla `exhibition_info` en Supabase no permite la operación de `UPDATE` para el rol o usuario que está intentando realizar la modificación. Esto podría deberse a:
    - Falta de una política `UPDATE` adecuada.
    - Una política `UPDATE` existente que tiene una condición que no se cumple (ej. `auth.uid() = user_id` y el `user_id` no está presente o no coincide).
    - La política está configurada para `INSERT` o `SELECT` pero no para `UPDATE`.
  Referencia: La documentación de Supabase sobre Row-Level Security es crucial para diagnosticar y corregir este problema.
Tasks / Subtasks:
  - [ ] Investigar las políticas de Row-Level Security (RLS) configuradas para la tabla `exhibition_info` en Supabase.
  - [ ] Identificar la política específica que está causando la denegación de la operación de `UPDATE`.
  - [ ] Modificar o crear una política de RLS para la tabla `exhibition_info` que permita a los usuarios autenticados (o al rol de administrador) realizar operaciones de `UPDATE` de forma segura.
  - [ ] Probar la funcionalidad de guardar modificaciones en `/admin/exhibition-info` para confirmar que el error de RLS ha desaparecido y que los cambios se guardan correctamente.
